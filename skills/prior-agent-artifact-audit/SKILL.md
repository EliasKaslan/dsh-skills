# 测试与交付证据审查

## 何时调用

**触发**：上一轮真的做完了吗 / 报告全绿可信吗 / 线上是哪一版 / 测试是不是漏跑 / 这条断言会失败吗。

**转交**：第三方漏洞报告复核见 [vuln-scan-report-verification](../vuln-scan-report-verification/SKILL.md)。

**前置**：恢复当前任务目标、输入与范围；缺少必需证据时如实标明。**后继**：交付可追溯结果与未覆盖项；编写或调整skill契约见 [dsh-skill-authoring](../dsh-skill-authoring/SKILL.md)。

先定义本次要核实的完成声明，固定源码SHA、依赖/平台、测试命令、构建和部署版本。报告、日志、自己运行和他人复核是不同来源，不是固定的可信度排序；原始日志也需核对其对应对象与完整性。

## 从发现到执行

列出实际测试文件、参数化case、CI selector/matrix、skip/only/filter、依赖和环境条件。数量对账要用同一维度：文件、suite、参数case与测试事件不能混算；不同平台合法skip可使本地与CI数不同。零case、cancelled、todo、collection error和缺rank都必须单列，不能因fail=0给PASS。

Node测试行为随版本变化：空glob、目录参数、timer unref、fetch保留头都在实际版本上最小复现，不写永久断言。协议安全测试先用受控接收端验证客户端真正发出的header/body，再判断服务端闸门。字段改名后断言须验证字段存在/类型，避免undefined导致不等式空转。版本断言按契约判断应比较构建版本还是固定兼容版本，不一律改读package.json。

## 测试能否识别缺陷

在隔离副本上做针对性变异/负控：改变关键分支或输入，确认对应目标用例失败，再恢复原副本复验。一次变异存活只说明该变异未被检测，不能独自证明整个测试无效。保护用户未提交修改，不能用checkout整文件回退实验。

核对被断言的文件是否是构建真实输入，并检查产物/加载模块和实际行为。构建后搜索唯一符号可辅助定位，但minify/编译/按需加载可能移除或改写符号；不能以字符串不在产物中直接判修改无效。构建ID应覆盖行为输入及版本工具，若存在非确定元数据则不强求还原后字节hash完全一致。

## 前序产物与部署

将源码、dist、安装包、历史快照、当前运行副本分开盘点。比较线上资源时记录URL、响应编码/压缩、动态注入和构建metadata；静态字节相同可证明该资源同一，不证明整个服务同一。安装同时检查运行时解析/启用路径，不能要求所有插件都有同一种“目录+清单”结构。

逐条复核旧报告的路径/行号、实际文件版本、命令返回码与证据覆盖。单处行号错不否定其余事实；PASS标记出现次数更不能计算“完成度”。能力声明需真实行为/测试证据，缺证据写未知；版本控制、CI、迁移/回滚只在交付目标需要时核查。

交付通过/失败/无效/未运行项及下一步；缺测试与功能缺陷分开报告。外部部署、生产请求和修复操作按本次授权，不为审查自动部署或重跑大负载。
