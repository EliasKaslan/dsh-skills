# 协议机制与验收

历史设计是 PC/手机各自出站连接 MQTT，主题 dshm/<room>/u|d，AES-256-GCM 封箱，URL # 携带密钥，AAD 绑定方向/主题。核查当版实现的 nonce 唯一性、认证失败行为、方向绑定、URL fragment 不被脚本/日志外传和重放控制。抓包看不到关键词不能单独证明端到端加密；本地已知明文/错钥匙/AAD 篡改/改密文必须产生明确可验证结果。公共 broker 可见流量元数据且不保证可用性，房间名不是权限边界。

- hello 不形成相互响应的无限循环；历史经验用至少10秒节流或只发送周期 beat。调节阈值以当前服务限制为准。
- 历史明文单帧24KiB（封箱约33KiB）优于96KiB，不是通用 MQTT 上限。分片 id/seq/total/d 需限制总片数、重组字节、并发数、过期时间，并处理乱序、重复、缺片和不同来源同 id 冲突。
- 超时重试沿用同一请求 id；服务端缓存结果，重复请求不再执行 POST。历史120秒缓存、4秒×4重试仅作起点；缓存寿命应覆盖最大重试/离线延迟，并约束内存。验证“产生一个任务”，不能只看两次响应相同。
- WS 回放合批可降低限流：历史40ms/24帧一批。保持原序号、关闭/错误语义和总帧数；不可把有序事件丢成仅最终快照。
- fetch shim 返回真正 Response，处理 gzip 解码后同步修正响应头，避免重复解压；WebSocket shim 对齐 EventTarget 与 readyState。是否禁用 EventSource、假 origin 与 service worker 相对路径取决于当版前端，先检查接口。

验收分层：本地协议模拟 → 授权 broker 的不含真实数据探针 → 手机视口读 UI/回放 → 经授权的一次无副作用任务往返。二维码渲染后解码与期望 URL 逐字符比较，输出报告只保留脱敏指纹。页面200还需内容包含目标构建标识；不要把固定1–3分钟部署延迟当保证。

静态托管必须给 HTML 合适 Content-Type；任何发布是独立外部写入。Git 匿名 ls-remote 成功不证明认证 push 可用；挂起也可能有隐藏 credential helper、网络或服务端问题，检查进程/提示配置，不直接下结论。认证沿用 github-pr-flow/github-pr-flow，禁止把 PAT 拼入 URL。重新生成链接、删 cloud.json 或改防火墙会影响当前用户，需在已授权的具体修复范围内操作。

## 建联、唤醒和多标签的故障判据

- 首次请求总失败而第二次成功：比较首次 send 与 transport ready 的时间戳。发送入口对未就绪做有限等待/取消，不立即失败，也不无限等。等待参数是实现选择，不固定8秒/50ms。
- HTTP 正常、WS 不推送：HTTP是独立请求而WS是长连接；检查旧隧道是否已废、连接所有权和close reason。不要先换broker或重新配对。
- connected=true/状态文件online不证明数据面可用；小beat正常而大响应全丢需探测半开或限流。用最近可信心跳、实际response和WS帧组合判断，UI离线状态须能随静默超时被推翻，恢复后撤销。横幅可能在body固定层，只读header的E2E会漏判。
- 唤醒后固定握手超时倍数重复 replaced by newer tunnel，且PC link closes=0/数据计数增长：查客户端connect是否重入后先teardown健康连接。区分connecting/OPEN时的普通重复调用与显式force重建；前台probe后给一个短验证窗，无帧再强制重建。headless/CDP不一定模拟真机冻结，真机复测单列未验。
- 记录close code和reason、业务拒绝码（bad-seq/bad-ts/bad-sid/replay）、脱敏sid前缀及tsDelta。bad-ts纠正时钟偏移后再限次重试；replay要区分运输seq与幂等业务id，不把同一业务请求变成新执行。非法身份/格式拒绝不能靠循环重试恢复。
- 多标签互斥按当前稳定页面身份和客户端选举实现；广播close必须核对是否属于本页，不能见到任何关闭帧就自杀。旧服务端按不稳定身份踢页曾导致互相顶替。控制帧与业务帧分别定义授权、新鲜度与幂等状态机，保护ack不被错误丢弃；不能为可用性一概移除控制帧认证/重放防护。

## 本机服务、发布与工作区

当前 core.mjs 传127.0.0.1给server.listen，和“relay自身只出站”分别陈述。核查Host/rebinding、WS Origin、CSRF、实际远程路由allowlist、relay marker先验证/降权再剥除。幂等缓存键至少绑定方法、规范路径、授权主体与业务id，避免GET结果误覆盖同id的POST。有限重放表被挤出后的安全语义需单独测试，不能沿用旧“宁可接受重放”的偏好。

静态外壳含代码也在信任边界内，链接fragment不上HTTP不代表其脚本读不到；localStorage保存密钥/token会使XSS后果扩大。审核真实markdown渲染器而非复制一份，使用无副作用载荷和阳性对照验证DOM是否执行；PoC硬编码“通过”字样不作证据，只看执行/转发计数与返回值。Node测试glob需先确认发现tests数量>0，不能把0测试exit0当通过。

前后端分别显示构建版本；发布后核对外壳构建哈希、目标代码标记和版本字面量，文件大小相同不能证明内容相同。UI缓存可能旧，分别确认shell和plugin来源。

新任务落到未分组时对照宿主已注册workspace与客户端cwd：自动检测的当前目录可能是未注册子目录，路径比较按Windows规则处理尾分隔符与大小写。选择器只提供合适已注册目录或明确显示未分组，不擅自把目录加入用户工作区注册表。

仅在用户采用tailnet直连的另一个架构中，检查服务Health/真实协调连接、接口范围、网络profile及实际端口；本机访问自己的tailnet地址不证明外部手机入站可达。修改默认端口不会改既有防火墙规则。不要为修复中继自动开Funnel/公网监听、改网络类别、重启服务或新增放行规则。旧daemon版还需检查管道继承句柄导致等待EOF、宿主作业kill是否带走孙进程、同一room是否多个执行者；Start-Process本身不保证脱离Windows Job，必须实际核对生命周期。
