# YB 文件任务桥

先确认仓库、分支、桥协议版本、方向、对端和本次授权（读取/发任务/回执/上传）。旧 yb.py 在 import 时读取本地配置，doctor 会访问账号，poll 会消耗本地 seen 状态；不要为“看看能否跑”直接 import 或执行 --help。GitHub 认证使用现有 github-pr-flow，秘密不放命令行/URL。

发送前写可判定的任务：目标、必要背景、可复制命令、每步预期/退出码、可写边界、禁止事项、需要回报的产物路径/字节数/哈希和失败证据。命令输出可能有秘密，先按上下文脱敏；不要求对端无条件逐字回传全部环境。将 task/message/correlation id 贯穿回执；“已收任务”与“已验收完成”分开。

读取时区分未消费预览和会写 seen 的 poll。先完整获取树/分页，遇 truncated 不报告没有新消息。校验 envelope 的协议、方向、任务id、总片数、每片唯一seq、总字节上限及 SHA256；缺片/重复片冲突不能拼成成功消息。详见 [原实现的审查与协议要求](references/protocol-audit.md)。

上传附件/发布和正文发送具有同样的外部披露风险；逐个扫描实际字节并复核目标仓库可见性，正则未命中不是“无秘密”证明。未经本次明确指示不新建任务、发送done、上传或publish，不因skill触发而获得发送授权。

本次已将scripts/yb.py同路径替换为exit78的退役入口，避免跨源认证及未检查附件外发。该桥的协议审查与任务合同仍可用；实际发送仅走已审查且当前公开的接口，不运行旧脚本或其备份。
