# 本机 UniVPN 排障

按当前客户端进程、配置、TAP GUID 和到目标的有效路由确认两套隧道的对应关系。历史路径可用来定位程序：主实例曾为 `C:/Program Files (x86)/UniVPN/UniVPN.exe`，第二实例曾为原安装目录下的 `.univpn-multi/UVP002/UVP002.exe`。启动前核实文件与实例归属；已配置自动登录时可直接启动对应客户端。旧实例包装器曾阻塞且未启动第二客户端，遇到这种情况先核对实际进程。

窗口收进托盘时主窗口句柄可能为零。结合客户端服务进程、TAP 的非 APIPA 地址、目标路由及 TCP 结果判断连通性。CS 日志周期性重打路由表可以是正常行为，需结合状态变动判断是否重连。操作界面时先查看当前状态，控件可能在切换会话后重建。

OpenSSH 在握手阶段超时时，可用相同目标、既有密钥和严格主机指纹校验的另一客户端交叉检查。两种客户端结果不同只说明该次连接路径或行为不同，需继续定位失败阶段。
