# Skill 沉淀协议

## 何时调用

**加载本 skill 当：**
- 任务收尾，要判定"这次做法值不值得沉淀"，或用户说"这套流程以后还会用""沉淀一下""把这个坑记下来"。
- 用户要求"写成 skill / 建个 skill / 更新那个 skill / **把这次的经验并进已有的 skill**"，或要改 frontmatter、description、`## 何时调用` 段。
- **每次非平凡运行收尾**都走一次 `## 9.` 的自动复盘与全库匹配，**不需要用户开口**。
- 发现近名 skill 可能已覆盖，需要决定"**融合更新**、**做总纲**、还是**新建**"。

**不要用本 skill（转交）：**
- 任务还在执行、没说要不要沉淀、要先拆解派活 → 用 `orchestrating-subagents`。
- 只是要改 `SKILL.md` 的 frontmatter / description / 「何时调用」段的**写法契约** → 用 `dsh-skill-authoring`。
- 只是要在单仓库里改一处已存在的技术正文 → 直接改，不走沉淀流程。
- 要定期体检整个 skill 集合（重复正文 / 失效指针 / description 预算），而不是沉淀某一条新经验 → 用 `dsh-skill-self-audit`。
- 本机 PowerShell 的坑（编码 / CRLF / BOM / PS7 语法） → 用 `pwsh-on-windows`。
- 派活前先确认子代理到底有哪些工具 → 用 `orchestrating-subagents` §3.1.1。

**前置**：有**已跑通**的证据包（真命令 + 输出要点 + 错误原文）。 ／ **后继**：写完按 `## 7.` 自验证；后续同类任务由 `orchestrating-subagents` 派活时复用本 skill 的规则。

## 0. 三段决策（先决策，再动笔）

收尾盘点后，**逐条经验**走这三段。**判定顺序固定为 ①→②→③**，因为 ① 的代价最低、③ 的代价最高（每多一条 skill 都推高**每个会话**的 prompt 成本）。

| 段 | 判据 | 动作 |
|---|---|---|
| **① 融合（默认首选）** | 这条经验**有归属主题**——某个已有 skill 的适用范围覆盖它 | **追加一节**，或**修正它里面已被证伪的断言**。不新建文件 |
| **② 总纲** | 经验暴露的是**一族** skill（≥2 个**总是一起用**，或构成一条**阶梯**）缺少**编排入口** | 建 / 更新一个**总纲 skill** 做编排入口（分层、生效时机、顺序、纪律），**子 skill 保持单一职责**；新知识写进总纲，与子 skill 重复的部分只留指针 |
| **③ 新建** | 以上都不成立（无归属，也不构成族） | 才新建 `<kebab-name>/SKILL.md` |

- **有归属却新建 = 过度沉淀**：等于制造两份将来必然不一致的真相 → 这是**错误**，不是风格问题。
- ② 的门槛是**族**，不是"相关"：两个 skill 只是同领域、可以分别单独使用 → **不建总纲**，做 ① 的交叉引用就够了。
- ② 的实例（实测）：DSH「改造 agent 行为」这个主题族由总纲 `dsh-agent-customization` 编排，子 skill 是 `dsh-isolated-web-host` / `dsh-agent-preset-verification`（含「阶段二」在线验收）——两者构成一条阶梯（起环境 → 离线 → 在线），各管一段，正文互不复制。

## 1. 判定（三个都"是"才写）

1. 这条经验**下次还会遇到**吗？
2. 它**真的跑通过**了吗？（不是"应该可以"）
3. 落盘位置按 `## 0.` 定下来了吗？（融合 / 总纲 / 新建，三选一）

有一条不满足 → **跳过**。**不要为了写而写**：会话专属的一次性数字、日志片段、临时路径、本次的结论数字都不属于 skill（见 `## 5.`），它们留在本次报告里。

## 2. 写哪里

| 内容性质 | 位置 | 说明 |
|---|---|---|
| 跨项目 / 工具链通用知识 | `~/.dsh/skills/<kebab-name>/SKILL.md` | 优先级 400 |
| 单仓库 / 单环境专属 | `<repo>/.dsh/skills/<kebab-name>/SKILL.md` | 优先级 100，覆盖 user 级 |
| 脚本、长参考资料 | 同目录包下的 `scripts/`、`references/`、`assets/` | **不进 skill 目录、不占上下文**，且改动不触发目录刷新 |

硬规则：
- 目录名 = `name` 字段 = kebab-case（`^[a-z0-9][a-z0-9-]*$`）
- 必须是 `<root>/<name>/SKILL.md` 或 `<root>/<name>.md`；**嵌套的 `**/SKILL.md` 不会被发现**
- 大段内容放 bundle 子目录，`SKILL.md` 里只留路径
- **① 融合**写进**已有 skill 的正文**，不新开文件；**② 总纲**也是 `<root>/<name>/SKILL.md` 一个新文件，但它**只放编排与纪律**，不放子 skill 的步骤细节

## 3. frontmatter

```yaml
---
name: kebab-case-name        # 必填，必须等于目录名
description: <唯一决定"何时调用"的字段>：≤480 字符、物理单行，必须含 适用于"<≥5 条用户口语触发句式>" 与 不适用：<场景> → 用 <反引号><兄弟 skill 名><反引号>
whenToUse: <≤150 字，给人和 API 看的一句话导航；模型看不到它，别指望它触发>
---
```

要点（写错就等于这个 skill 不会被想起来）：
- 模型每步只看到目录里的 `- \`name\`: description` **一行**；正文和 `whenToUse` 都不参与触发判定。
- `description` 超 **500** 字符会被截断成前 497 + `...`，所以**触发句式必须靠前**，写太靠后等于没写。
- 旧的 `description: 一句话写清【触发场景】` 这种写法（无触发句式、无消歧）**已不合规**，缺 适用于"…" 或 不适用：… → 用 <反引号><兄弟 skill 名><反引号> 会被校验器判 FAIL。
- 好（形状）：<领域锚点>——<关键能力/实测要点>。适用于"<触发1> / <触发2> / <触发3> / <触发4> / <触发5>"。不适用：<场景> → 用 <反引号><兄弟 skill 名><反引号>。
- 差：`vllm-ascend 安装说明。`
- 契约细节（字符数怎么量、全角冒号、camelCase 键会拒载、校验脚本）见 `dsh-skill-authoring`，本 skill 不重复。

## 4. 正文模板（骨架，`## 何时调用` 四要素缺一不可）

```markdown
# <标题>

## 何时调用
- 触发信号：<用户原话 / 报错原文 / 命令输出里可观测的东西>
- 转交边界：<场景> → 用 `<确切兄弟 skill 名>`
- 前置：<没有就做不了硬条件> ／ 后继：<做完通常接哪个 skill>

## 前置检查
环境 / 版本 / 依赖 / 权限，以及怎么快速确认（给命令）。

## 步骤
1. <目的>：`<可直接复制粘贴的真实命令>`
   - 验证：<怎么知道这步成功了>

## 坑与修法
- 现象/错误原文：`<错误信息>`
  → 原因：<...>
  → 修法：<命令或改动>

## 不要做什么
已知的死路，避免下次重走。

## 验收标准
完成时应该观察到什么（命令返回、文件存在、输出字段）。
```

**总纲型 skill（第 ② 段）的正文形状不一样**：它不写子 skill 的步骤，而是写「**分层与生效时机表 → 上线纪律 → 阶梯顺序（谁在什么时候调谁）→ 每层怎么撤 → 验收标准**」，并在 `## 何时调用` 的转交边界里把每个子 skill 都点名。

## 5. 内容质量硬要求

- **每条命令必须真执行过**，把实际用的那条写下来（含路径、参数）
- **坑必须附错误原文**——错误原文才是下次能被搜到的锚点
- 写"怎么做"，不写"要小心"；禁止通用建议（"要注意版本兼容"这种）
- 有环境假设就写死（IP、路径、版本号），不要写"某台机器"
- **会话专属证据留报告，可复用方法才进 skill**：本次的数字、日志原文、临时路径、一次性结论 → 报告（或交付说明）；**能迁移到下次的判据、命令、错误原文、纪律** → skill。分界线是"换个任务还用得上吗"。
- 不确定的地方标 `未验证：`，不要写成结论

## 5.1 目录税预算（新建 / 追加 skill 之前的硬闸门）

先认清**机制事实**：skill 目录税 = **条数 ×（name + description）**，**与正文大小无关**（正文只有被加载才进上下文，`dsh-skill-authoring` F6）。
实测（2026-10-22）：目录 **35 条**；单条增量 = `len(name) + len(description) + 7`，闸门 = 目录字符总量 **20,000**。**本行不给字符总数、不给 token 估算**（该量现有 ≥5 份互不相同的读数：14,328 / 14,495 / 14,658 / 14,664 / 15,359，**不满足"可独立复现"**） ⇒ 按 `~/.dsh/AGENTS.md` §9.7 的判据纪律，它不得被当判据；
且它**每一轮**都注入主 Agent 与 `subagent` 类子代理（**`explore` 类实测不注入**）⇒ 每加一条都是永久抬高所有未来会话、所有 agent 的固定税。

**三条硬闸门**：

1. **报数**：新建 / 追加 skill 之前，**必须先报出"这条给目录增加多少字符"**。报不出这个数 = 闸门没过。
2. **判决顺序不变、但加一条量化倾向**：仍是「有归属 → 融合 → 构成族 → 总纲 → 都没有 → 才新建」，**再加一句：能融合进已有 skill 的，一律融合**——新建只是最后手段，不是默认动作。
3. **超预算先合并**：目录字符总量超预算时，**先合并再新建**。**默认预算 = 目录字符总量 ≤ 20,000**（这是本部署给目录留的常驻上限，覆盖 name + description + `- ` + 换行）；**它是可调参数**，按各自部署实测的会话目录字符总量重新定，不是硬编码真理。

**描述预算已吃满的证据**（不许再拿"还有余量"当理由）：35 条 description **中位数 456 = 上限 480 的 95.0%**，且 **14/35 距警告线不足 16 字符** ⇒ 任何一次"再补一条触发词"的常规编辑都会把过半 skill 推过 480。**⇒ 新增 skill 的默认结论应是"融合"，不是"新建"。**

**削描述的铁律：只削"实测数字 / 证据"，绝不削触发句式。** 理由：目录是**唯一触发通道**（模型只看到那一行）。把 10 条 `ascend-*` 并成 1 条，等于要把 4,496 字符的触发句式挤进一个 ≤500 字符字段 ⇒ **可触发性掉约 90%**；那是**拿召回换字符**，不是优化。
同理，事后靠截尾（`dsh-skill-self-audit` §3 的自动项）会砍掉**尾部**触发句式 ⇒ 与其事后截尾，不如事前不写。

## 5.2 写手无 shell 时，闸门怎么落地（2026-10-09 实证：`distill_skill` 通道无 `pwsh`）

沉淀子代理**可能拿不到 `pwsh`**（本轮实证：函数面只有 `read` / `write` / `edit` / `grep` / `glob` / `skill` / `subagent`）。此时 `## 5.1` 的报数闸门、`## 8.` 的写前哈希、`## 7.` 的"用命令量长度"**全都跑不了**。**不许绕、不许估、不许假装落盘**——按下面五条落地：

1. **测量值一律留空并标注**：交付次行按契约写 `交付物: <绝对路径> 字节数: 无该能力`——**不许估**（估值不是证据，见 `~/.dsh/AGENTS.md` §4），**也不许省掉路径**。`description` 长度、目录税增量、sha256 同理：写"未测 / 无该能力"，**不写估出来的数字**。
   - 反例（本轮实际发生）：我按段估 `desc_len≈460`，Lead 实测 **578** ⇒ **估读偏差量级可达 25%**，恰好跨过 480/500 两道线。**估算值不能当闸门判据。**
2. **用旁证替代自测，并显式标注"这是旁证不是实测"**：改前 `read` 全量、改后**立即重读 + `grep` 唯一锚点命中**（锚点要选每次改动都唯一的那句）；本会话 skill 目录里该条**不再显示截断 `...`** ⇒ 尾部完整 ⇒ ≤500（**只否掉截断线，证不了 ≤480**，如实写清界）。
3. **把跑不了的闸门逐条列给 Lead，并附可直接复制的命令**（形状即：`python -c "…len(description)…"`、`python -c` 读 hunk、`Get-FileHash -Algorithm SHA256`）。**判据留在 Lead 侧**——这是分工，不是失败，也不是"绕"。
4. **声称落盘的文件若没搬，就如实说不落**：原因 + 替代位置**写进 SKILL.md 正文**（本轮对 `FORMULAS.md` 就是这样：正文写明"未复制进本目录、仍在 `<原路径>`"），**不在正文里谎称已落盘**；同理，凡"读源 + 逐字重写"搬运（本写手无 `cp`）都要在正文标注**未做 sha256 逐字节比对**、有差异以源文件为准。
5. **反向纪律（Lead 侧）**：**不得把"有 shell"当成默认前提下发**。需要 shell 的验收判据（哈希 / 长度 / 真跑校验器 / 逐字节比对）**要么写在 Lead 侧、要么派给表内带 `pwsh` 的通道**；并在 prompt 里**不要把工具面广告成"完整工具集"**（本轮该广告即被证伪）。工具面预检 → `orchestrating-subagents` §3.1.1。

**收敛判据**：无 shell 的沉淀子代理，**合格交付 = 内容写对 + 闸门空缺如实标注 + 可复现命令交给 Lead**；**不是**"自己造一个数字把闸门填满"。

## 6. 单一归属与维护（防重复 / 防过度沉淀）

- **单一归属**：同一条经验只写在**一个** skill 的正文里；别处只写**指针**（"→ 用 `<skill 名>`"）。重复正文 = 制造将来必然不一致的两份真相。
- 写前先 `skill` 加载近名 skill → **有归属就融合更新**（第 ① 段），不新建。
- **融合 / 新建后必须同步维护两处**：
  1. **`description`**——它才是决定"何时调用"的字段。经验变了而 `description` 没变，等于新知识不会被想起来；`description` ≤480 字符、**物理单行**。
  2. **「不适用 → 用 X」交叉引用**——**双向都要成立**：新 skill 指向兄弟 skill，兄弟 skill 也要能指向它（总纲 → 子 skill，子 skill → 总纲）。单向引用等于半个入口。
     - 写「→ 用 `X`」前先确认 `X` **真能加载**：**目录里没有 `X` ≠ `X` 不存在**，可能只是它的 frontmatter 坏了（判存在看磁盘、判可用看目录；校验见 `dsh-skill-authoring`）。
- 合并时保留原有的坑，追加新的坑；**修正被证伪的断言**要和追加新知识一样重要（旧结论不改掉，下次还会照错的做）。
- **② 的总纲不是目录索引**：只列"有哪些子 skill"没有价值（模型本来就看得见目录）。总纲的价值在于写进**子 skill 里没有的**新知识——分层与生效时机、上线纪律、顺序与为什么不能跳、回滚矩阵。
- user 级 skill 总数控制在 **~30 条**以内；超了先做一轮合并再写新的。

## 7. 自验证（写完必做）

first-party `write`/`edit` 会同步让 skill provider 失效，因此：
1. 写完下一步，会话 skill 目录里应出现该条目（无需重启）
2. 用 `skill` 工具按名字加载一次，确认正文可读、frontmatter 没写坏
3. 若目录里没出现 → 检查：目录名是否 kebab-case、是否在扫描根的一层内、frontmatter 是否有非法值（**新建目录**比改已有文件更容易漏，见 `dsh-skill-authoring` §7.5）
4. 校验四要素：`description` ≤480 字符且物理单行、含 适用于"…"（≥5 条触发句式）+ 不适用：… → 用 <反引号><兄弟 skill 名><反引号>、`whenToUse` ≤150 字、正文含 `## 何时调用`（触发/转交/前置/后继齐全）
5. **跑交叉引用自检**：新写的指向真的存在；被指向的兄弟 skill 的 `description` 里也能找到本 skill 名（双向成立）
6. **`description` 长度要用命令量**，别靠眼看——中文一行 400+ 字符时肉眼估不准（实测：估"差不多 450"，实际 626）

## 8. 谁来写

优先**委派沉淀子代理**（`distill_skill`，若可用）并附上"证据包"：
已跑通的命令 + 输出要点 + 错误原文 + 修法 + **本次经验的逐条清单（供它做第 0 节三段决策）**。
写文件不占主 Agent 上下文。只有单条小修（改一行 `description`、加一条坑）时才自己做。

> **子代理供给**：下发前在 prompt 里点名让它 `skill` 加载 `sedimenting-skills`（本 skill 的沉淀协议与三段决策）与 `dsh-skill-authoring`（skill 文件契约）。加载不到（工具受限的子代理）就把 `C:\Users\admin\.dsh\skills\sedimenting-skills\SKILL.md`、`C:\Users\admin\.dsh\skills\dsh-skill-authoring\SKILL.md` 路径给它 `read`。机制与判据见 `orchestrating-subagents` §3.1。

**并发警告**：`~/.dsh/skills` 是**多个会话共享**的目录，别的会话可能正在写同一个文件。
→ 每次写前**先 read**、写后**立即重读确认**；文件在两次读之间变大/变小/时间戳跳了 = 有并发写入者，**先停下问用户**，不要回滚、也不要"顺手修正"别人的改动。

**改前先留哈希**（2026-10-08 实测教训）：动**共享库** skill 之前，先
`Get-FileHash -LiteralPath <该 SKILL.md> -Algorithm SHA256` 把值记下来。
血证：同一次改动没留哈希，事后回滚只能靠"字节数 + 行数 + 反向锚点各唯一命中"**推断**自己逐字节还原了，
**拿不出哈希证明**——而剥 BOM、换行差异这类问题恰好是这种推断抓不到的。


## 9. 运行收尾自动复盘与全库归属匹配

**触发时机**：非平凡运行（用过工具 / 有试错 / 跑通了新流程）**收尾时自动执行**，不需要用户说"沉淀一下"。
本轮确无可复用内容 → **明确空手而归**并给一句理由：**允许不沉淀**才是防"为写而写"的机制。
（触发时机的判据在 `~/.dsh/AGENTS.md` §8——**唯一出处**；**配方在这里**。）

**步骤 0：先立「经验清单」**——把本轮**真跑过**的东西逐条列成 `命令` + `输出要点` + `报错原文` + `修法` 四元组；
只用已发生的事实（"应该可以"的东西不进清单）。会话专属的数字 / 日志原文 / 临时路径 → 留报告，见 `## 5.`。

**步骤 1：全库匹配（不许只看近名 skill，不许凭印象挑一个）**

1. **圈候选**：会话 skill 目录里已列出**全部** skill 的 `name` + description（一条一行）→ 据此圈 2~3 个候选。
2. **落地检索**：拿经验里的**高区分度锚点**（报错原文片段 / 命令名 / 平台名 / 版本号）扫**全部** skill 正文。
   **首选 `grep` 工具**（`path` = `~/.dsh/skills`、`include` = `SKILL.md`）——它不踩本机 PowerShell 的编码坑；
   要在 `pwsh` 里手跑就用下面这条（**实测通过**：锚点 `TEAM_NOT_MEMBER` 命中 `dsh-agent-customization`
   与 `dsh-agent-preset-verification`）：
   ```powershell
   Get-ChildItem "$env:USERPROFILE\.dsh\skills" -Directory | ForEach-Object {
     $f = Join-Path $_.FullName 'SKILL.md'
     if (Test-Path -LiteralPath $f) {
       $hit = Select-String -LiteralPath $f -Pattern '<锚点>' -SimpleMatch -Encoding utf8 -ErrorAction SilentlyContinue
       if ($hit) { '{0}  <- first hit line {1}' -f $_.Name, (($hit | Select-Object -First 1).LineNumber) }
     }
   }
   ```
3. **确认归属**：对命中的最强候选用 `skill` 工具**加载正文**再判。判据是**候选的适用范围覆盖这条经验**；
   命中只说明"提到过"——同一条命令在别的场景出现**不算归属**。
4. **两种命中同样重要**：
   - 该经验**已被写过** → 本轮往往**不需要写**（最多补它缺的那一句）；
   - 它写过但**结论已被本轮证伪** → 这是**修正**，优先级**高于**追加新知识（见 `## 6.`）。
5. **确认没有归属**才能进「新建」分支——`## 0.` 的 ③ 段要求"以上都不成立"，**全库零命中**才是这一段的证据。

**步骤 2：决策与落盘** → 走 `## 0.`~`## 7.`，本节不复述。

**收敛判据（防过度沉淀的闸门）**：一轮里**新建 0 个 skill 是完全正常的结论**；
真正要能回答的是"这条经验进了哪个已有 skill 的哪一节"——答不出来才考虑新建。

**并发写手纪律**：`~/.dsh/skills` 多会话共享 → 写前 `read`、写后**立即重读**；两次读之间内容 / 大小 / 时间戳变了
= 有并发写入者 → **停下问用户**（同 `## 8.` 末段）。
