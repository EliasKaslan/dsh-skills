# DSH委派编排与能力预检

从当前会话权威工具目录/schema确认委派方式、provider/model策略、深度和可写范围；旧explore只拿5个工具的观察不是所有版本定律。模型自述“我有工具/我没工具”可作线索，不能代替目录或一次最小只读调用。

委派前给出目标、必要上下文、可写路径、输入、完成判据和回报格式；拆独立子任务，明确共用文件的唯一写入者。需要网络/命令/落盘的任务必须给具备相应能力的角色，不让只读探查角色承诺写文件。受限时及时调整任务或改派，不能把一堆未验证条目当完成。

能力预检仅验证必要能力：现有无敏感文件的读取、无副作用命令或当前schema查询。不要为验证写权限往真实配置/账号目录写哨兵，也不发邮件、创建外部任务或调用具有业务副作用的工具。子代理工具允许/禁止与schema可见性分别检查，动态注入可能扩展原allowlist。

回报包括证据文件绝对路径、哈希/字节数、实跑命令和退出码、失败及未验项。接收方读产物并做与风险相称的独立复核；原始字节一致用SHA256，规范化文本相等不能称逐字节相等。遵守当前用户和宿主指令，不用固定行数/文件数强制委派，不自动启动goal或改变全局行为。
