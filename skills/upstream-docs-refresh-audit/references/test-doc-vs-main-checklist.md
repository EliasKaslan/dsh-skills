# 转测文档 → 主线 docs 逐项核对清单

用途：当外部输入是**转测文档**（中文 .txt，声明「该需求实际交付并验证了什么」）时，用它逐项核对主线 docs 是否让用户检索得到。
实测来源：2026-09-28 第二轮，`D:\workspace\260928_vllm资料确认\转测文档_2026Q3\*.txt`（12 份 / 165KB / 最大 50KB），主线 = vllm-ascend `f18d103838b8`，交付 `vllm-ascend主线资料刷新清单_v2_转测文档校核.md`（336 行）。

## 0. 判据先立住

- 转测文档声明「已交付并验证」= **已交付事实**，不再猜型号/场景。
- 要判的只剩一件事：**该能力能否在主线 docs 的单一页面按型号/场景检索到**。跨页拼凑不算。
- 每条结论必须给两侧 file:line：转测文档 `<file>:<line>` + 主线 `<file>:<line>`。

## 1. 逐项核对表（每份转测文档各填一遍）

| # | 核对项 | 怎么查 | 判定落点 |
|---|---|---|---|
| 1 | 公开模型名/权重名能否在 docs 检索到 | `git -C <repo> grep -F -i -l -- "<公开名>" -- docs`；权重路径里的私有目录名（如 `-novit-no-o`）单独 grep | 0 命中 → 教程页/矩阵行待新增；命中 → 记 file:line |
| 2 | 硬件代际的内部写法是否与 docs 一致 | 转测写 A3/A5/A2 → docs 写法 `950DT Products` / `950PR&950DT Products` / `A2/A3`；`git grep -F -i -l -- A5 -- docs` 作为反例 | 用 docs 写法落笔；A5 必须做映射，不要直接写「A5」 |
| 3 | 精度格式是否有落点 | BF16 / W8A8 / W4A4 / W8A8-MXFP8 逐个查：矩阵列（`supported_models.md` 表头是否有该列）+ 教程章节 | 矩阵无此列 → 记「新增列」；仅 Note 自由文本提到 → 记「未成列」 |
| 4 | 转测用到的每个环境变量/启动参数在主线是否存在 | `git -C <repo> grep -F -i -c -- <VAR>`；`git -C <repo> log -S"<VAR>" --all --oneline` | grep 0 命中且 log 0 提交 → 点名进风险，**文档不得照抄** |
| 5 | 转测实测数值 vs docs 数值 | 冲突时以**转测为准**（它是实跑结果），记录双方 file:line | 主线其余值记「待统一」 |
| 6 | 转测文档缺字段 | 逐份看「实验环境 / 服务器拉起 / 日志 / 结果」小节标题下有无正文；查硬件代际、公开模型名字样 | 标 **TBD / 待业务确认**，不得臆断，方格里留 🟡 |

## 2. 已实证的两个判读细节

- 一个转测开关「找不到 ≠ 转测写错」：本轮 `VLLM_ASCEND_DSV4_KV_BF16` 在 `【A5】A5支持DS V4 flash高性能推理.txt:75,133,211,270` 与 `【A5】Rollout阶段vllm支持MXFP8格式推理（deepseekv4 flash）.txt:77,134` 出现，但与 `--kv-cache-dtype bfloat16`（同文 `:83,142` / `:86,143`）**成对出现**，而主线只认后者（`DeepSeek-V4-Flash.md:1196`、`DeepSeek-V4-Pro.md:1524`）。结论写「两者并存，主线只认后者」。
- 转测数值裁决主线冲突的范本：`--max-model-len 1024000`（转测四机一致）裁掉主线 `1048576`（`GLM5.2.md:1273,1337,1399,1462`）与 `198k`（`GLM5.2.md:1654-1661`）+ 矩阵 `200k`（`supported_models.md:43`）。

## 3. 输出格式（每条需求）

```
### REQ-XX <需求原文>
- 转测文档要点：<硬件代际 / 公开模型名或权重路径 / 精度格式 / 配套版本 / 启动参数 / 性能与精度数值 / 测试结论>
- 映射与证据：转测 <file>:<line> ↔ 主线 <file>:<line>
- 代码/资料现状：已有 :行 什么；缺什么（逐文件）
- 需刷新的文件 + 章节 + 具体补什么
- 存疑点：<缺字段 TBD、开关不存在、数值冲突，各带 file:line>
```

硬要求：`gaps_or_risks` 里出现的每一项 TBD 都要在刷新方案的对应列写「待业务确认」；数值冲突两侧 file:line 必须都写出来。
