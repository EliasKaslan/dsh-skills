# DeepSeek V4.1 Flash L4：Ascend 950 上的训推对齐

案例 ID：2026-11-15-dsv41-flash-l4。状态：**VERIFIED_SCOPED**。实现验收于 2026-11-15，项目 CPU 证据复核及实现文档整理于 2026-11-16。

本案例的固定输入矩阵上，θ0/θ1/θ2 每策略 64 个有效 FP32 token，推理 decode/refeed-prefill、原生 old-logprob、真实 grad-enabled forward 原始位相同，logpdiff mean/max/p95=0。完成连续两次真实 AdamW response-NLL 更新和两次同一组四个驻留 worker 的在线同步。这是 L4 文本验收，不能外推完整模型、稀疏截断后的长上下文、完整 RL 算法质量或长期训练。

## 关键差异、修改与迁移条件

| 观测/问题 | 本轮改动 | 新任务可借鉴的条件与限制 |
|---|---|---|
| mHC 对行数/偏移敏感，两侧原实现不同 | 共享训练 CANN delayed-premix pre/post；独立行按 128 补齐/裁剪；训练保留真实 backward | 固定 launch 几何是候选方法；128、hc_mult=4、20 次 Sinkhorn 和当前 vendor 仅属本例 |
| 混批 replay 后层调用第 0 层 MoE 专家 | 嵌套 ForwardContext 进入/退出传递 moe_layer_index | 先查语义/层身份，不把所有混批差异当低位误差 |
| token 数改变通信路径 | BI 下 EP>1 固定 AllToAll | 可固定或核对通信选择；其他拓扑不应直接锁定本例 backend |
| RMSNorm 的路由输入舍入不同 | BF16 norm 输出后再 float 做 gate linear | 高精度中间值不等于低精度舍入后的高精度表示 |
| router math 与归约路径不同 | 匹配训练 sqrt-softplus 稳定分支、bias 只选索引、无偏概率归一化、FP32 weights | 无 tid2eid、单组分支实测；未覆盖 hash/多组/视觉 bias |
| routed combine 和最终相加不同 | FP32 unpermute 后 BF16；scale=1.5 后置；routed/shared FP32 相加后一次 BF16 | 对齐 cast/scale/sum 的顺序，不只是公式 |
| 长样本层 2 共享专家 SwiGLU 有 2 个 BF16 值不同 | 共享分支 FP32 clamp/fused SwiGLU 后 BF16；路由专家保留训练 BF16 fused | 共享与路由分支精度契约不同，不能一刀切 |
| RoPE 表和旋转差异 | 显式 CPU arange/polar、匹配 YaRN 运算次序，FP32 even/odd 旋转后 cast | 工厂默认设备、表达式顺序、布局都要验证；CPU 建表不作通用要求 |
| BF16 KV 与旧 packed spec/metadata 不匹配 | 修正 cache ABI；BF16 metadata 为 2048 int32；paged 使用 PA_BBND；无压缩 ratio 0→1 | metadata、layout、ratio 数值属于当前 CANN 绑定，换版本重新读 schema |
| 原生 SparseMLA 输入连续性/长度契约 | TND B=1，q/ori/cmp KV contiguous，奇数长度右补到压缩比例 2，保持有效 mask | 不自动适用于双向/左 padding/其他 packing |
| 模型 logits 相同后 LP 仍有差异 | 训练自身 FP32 logits 调用实际 Ascend V2 scorer，补一阶解析 VJP | 实际 scorer block=12944 与通用上游不同；不将 block 作为新模型默认 |
| 全局 BF16 转换和分片 owner 问题 | 保留显式 FP32 参数；owner 分组、子先父后；显式模块计算 dtype | 需要按当前框架支持验证，不是通用修改模板 |
| 更新后 FP32 router shadow 与导出值不同 | gate 从接收存储起保留 FP32；逐 worker/层核对实际 shadow SHA | 同步字节和实际计算副本都要查，初始对齐不能代替更新后验证 |
| 全局专家 NPU gather OOM | CPU/Gloo 逐专家流式导出，验证 global coverage | 本例仅支持指定连续 Shard(0)；其他 placement 需另实现 |
| reload 特殊参数和文件生命周期 | sink 走官方 loader；全 DP ACK；仅 clone 本 rank 专家，释放 mmap 引用 | 不照搬 TP1/DP4/linear/no-EPLB 的过滤；检查全部接收端和派生状态 |

修改主体是现有 CANN kernel 复用、精度/布局/调用几何和框架 glue。没有新写 CANN mHC/SparseMLA/ScatterNdUpdate 二进制 kernel。稳定 router 数学、部分 autograd 和 vendor 绑定来自已有训练实现，不能计为新开发。

## 支持归因的探针

- mHC pre 四个输出跨栈相同、post 相同；偏移 0/1/7/17/63/120/127/128/255 均通过。输入、phi、alpha、bias、premix 梯度有限非零；此项不等于完整独立数值 gradcheck。
- 8×5120 MoE 探针：路由权重相同但旧 routed 输出有 13343 个差异；FP32 unpermute 后 routed/shared 相同。旧 BF16 最终 combine 仍有 9494 个差异、max_abs=0.0625，FP32 combine 为 0。
- 127-token 长样本：层 0/1 相同，层 2 共享激活 2 个值不同、max_abs=6.1035e-5，down projection 扩散到 169 个值；共享 FP32 激活修复后捕获的层 0/1/2 激活复算为 0 差异。
- scorer 8-token 探针：原生 CANN LogSoftmax 对推理 6/8 不同、max_abs=4.768e-7；使用实际 Ascend V2 scorer 后 0/8。解析 VJP 对独立 log_softmax autograd 测试通过，rtol=2e-6、atol=2e-7；只支持一阶导数。
- 大 strided INT8 indexer cache 的 ScatterNdUpdateSk workspace 约 69.14 GiB 导致 OOM/超时；限制 128 页后测试可运行。这是容量修复，不是 SparseMLA 数学或 ScatterNdUpdate kernel 修复。

## 更新与同步链

最终通过链 v5 从原始 checkpoint 开始，θ0/θ1/θ2 各比较 64 token，单独/混批/逆序、decode/prefill、old/grad 前向均为原始 FP32 bit mismatch=0。

| 更新 | grad norm | 各 rank 变化的本地参数张量数 | optimizer counter |
|---|---:|---|---|
| 1 | 29.410503387451172 | 76/76/75/67 | 1 |
| 2 | 28.508363723754883 | 76/76/75/67 | 2 |

核对 update1 after shard SHA=update2 before shard SHA；两次同步各 106 包，全部四 worker ACK、level3、版本和实际 FP32 router shadow SHA 通过；保持相同 worker 身份。两次同步约 500.472s、342.820s。不同 effective-policy 指纹验证部署版本变化，指纹由导出名称/shape/dtype/tensor SHA 清单计算，不是全量 checkpoint 文件 SHA。

诊断 v3 在一次更新后导出 OOM，v4 在一次更新后发现 router shadow 精度丢失，均单独作废归档；它们不混入最终连续两步链。任务在原授权窗口内释放资源。历史授权已结束。
