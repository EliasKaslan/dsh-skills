# 跑分缺席与证据分层（判别细则）

正文只留判据，完整探针与分层清单在此，用到时再读。

## 一、零条目的三种原因，不得混写

| 现象 | 真实含义 | 结论栏应写 |
|---|---|---|
| 模型页或路由 404、榜单无条目，但产品已可用 | 未开放公开端点或未开源，榜方拿不到可跑对象 | 未送测 |
| 榜上有条目但分数明显低于同代 | 已送测且真跑过 | 跑输了，写具体差距 |
| 只有盲测代号行为（如 X-Preview），无正式条目 | 众包对战阶段 | 代号观察，不等于可引用排名 |

典型探针：

- Artificial Analysis：https://artificialanalysis.ai/models/<slug> ，404 即无条目；厂商页 https://artificialanalysis.ai/models/creators/<org> 列已收录型号（2026-11-23 只复测了 leaderboards / agents 两条路径可达）。
- OpenRouter：https://openrouter.ai/<org>/<model> ，404 即无路由；无路由即无调用量与排名。
- HuggingFace：https://huggingface.co/api/models?search=<name> ，返回 `[]` 即未开源。
- SWE-rebench、Terminal-Bench、tbench.ai、swebench.com：表为 JS 渲染或需登录，抓不到只能写「未能举证」，不要反推「没有」。

## 二、证据分层（引用时必须标层）

1. 机构级独立复跑：AA、SWE-rebench、Arena Elo。同 harness 内才可横比。
2. 厂商自报（含官方群、官号转述）：只证明官方这么说，不证明水平。
3. 个人榜：博主自测，题量常个位数、无审计、可能是 6 题 60 分制。只当参考；名次比百分数更不可靠，榜会随新模型入场重排。
4. 社区手测：有调用痕迹（额度页、账单、界面截图）才可信；主观、样本小。
5. 泄露与传闻：无复现脚本，标传闻，不进结论。

## 三、效率看三量，不看 TPS

同一任务集分别记：wall time、工具调用步数、reasoning token 量。三者可各差一个量级。
「每步耗时相近但步数多一个量级」= 模型在打转，不是网络或 TPS 问题。
高 effort 档常见「性能小涨、时长与大增」，引用时要同时给耗时，否则低估使用成本。

## 四、混合态（订阅先发、API 后开）

此时三个证据面会同时成立且互相矛盾：用户有实测、榜上零条目、官方零跑分。
交付时逐项标源，不要取其一；结论只能写到某维度上升或下降，不能给总排名。
